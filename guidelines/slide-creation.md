# スライド作成ガイドライン（全クライアント共通）

> このマニュアルはクライアント向けスライドを作成する全エージェントの基本ルール。
> `knowledge/lessons/` のケーススタディを反映して継続的に更新する。

---

## 0. 作業の前提（必読）

### 必ず守ること

1. **`core-rules/data-hygiene.md` を遵守**：他クライアント情報の混入禁止
2. **対象クライアントの knowledge/clients/<client>/proposal-patterns.md を必ず読む**
3. **対象データの全シートを舐めてから着手**：途中シートに重要データが眠っている可能性

---

## 1. 構成設計の標準

### 月次定例の標準構成（推奨）

**3章構成にまとめる**：細かく9〜10章に分けず、論理ブロックで集約する。

```
1. 〇月振り返り
   - 着地サマリ（数値ハイライト）
   - 商品別動向
   - 検索KW分析
   - 競合比較
   - 個別施策の効果検証（爆買week／アイテムリーチ等）

2. 〇月ご提案
   - 売上計画（イベントカレンダー＋日別推計）
   - 施策一覧テーブル（想定効果まで具体数値）

3. ご相談事項（必要に応じて）
   - 配送・運用・契約等の意思決定が必要な事項
```

### NG構成（実際にやってしまった例）

- セクションを9つに切って、各セクション1〜2スライドずつ並べる
- 「KPI比較」「チャネル別」「検索KW①」「検索KW②」「商品別」「爆買week」「4/18分析」「優良配送」「5月施策①」「5月施策②」「5月施策③」「ToDo」のように細分化しすぎ
- → 読み手の集中が分散する。論点が埋もれる。

## 2. データ提示の標準

### 数値の出し方

**◎ 推奨**

| 想定効果（営業的・具体的） |
|---------------------------|
| 売上20万円 / 新規獲得30名 |
| ROAS200%以上維持しつつ経由売上15万円 |
| 売上1.5万円 |

**× 抽象的・不十分**

| ふわっとした効果 |
|------------------|
| 日次平均6,000円の底支え |
| 露出獲得 |
| 広告効率改善 |

### 各施策テーブルに必ず含める列

`施策名 / 実施日 / 内容 / 想定効果（数値）`

### 着地推計の出し方

- 単に月平均から計算するのではなく、**残日数の各日に売上見込みを置く**
- 例：「4/27日 5,000円、4/28日 7,500円、4/29日 7,500円、4/30日 5,000円」
- → 何故その金額か理由が説明可能（販促カレンダー連動）

### 数値の根拠

- どのシート・どの行・どの集計か必ず手元に控える
- 質問された時に即答できる準備

## 3. トーン・表現の標準

### 達成度評価のトーン

| 状況 | NGトーン | OKトーン |
|------|---------|---------|
| 達成見込み99-101% | 「達成圏」「ほぼ達成」 | 「ギリギリのライン」「すべての日程で目標達成必要」 |
| 達成見込み90-98% | 「あと一歩」 | 「未達リスクあり、〇〇の挽回必須」 |
| 達成見込み80-89% | 「順調」 | 「未達濃厚、要追加施策」 |

### 仮説と事実の分離

- 「〇〇という結果が出ています」（事実）
- 「〇〇と推測されます」（仮説）
- → 推測を事実っぽく書かない

### 過剰な深掘りを避ける

- ある異常値（例：1日だけ売上0円）の原因について **4つも仮説を並べる必要はない**
- 表内コメント1行（「（一時、在庫切れ影響あり）」等）で十分なケース多数
- 仮説の羅列より、**次の確認アクションを1つ提示する**方が建設的

## 4. 競合・市場視点を必ず入れる

月次資料の重要要素として、以下の比較スライドを必ず設計検討する：

### 競合比較スライド

- ベンチマーク2〜3ストアと自店を並べる
- 評価軸: 食べ比べ／価格／クリエイティブ／レビュー数／優良配送 等
- 〇△◎×で簡潔に
- 結論メッセージを1行で（例：「食べ比べの露出を強化し、新規ユーザー・レビューの獲得が重要」）

---

## 5. デザイン・装飾

- クライアント色（中立・シンプル）：白背景、黒/濃グレー文字、控えめなアクセント1色
- 装飾・記号（→ ✅ ❌ ★ 等）は **極力使わない**
- 装飾より情報密度・読みやすさを優先

---

## 6. 完成時のセルフチェック

- [ ] 他クライアントの固有名詞が混入していないか（grep）
- [ ] 各施策に数値ベースの想定効果があるか
- [ ] 曜日・日付は一次データと一致しているか
- [ ] 推測と事実が混在していないか
- [ ] 競合比較／市場視点が入っているか
- [ ] 全体構成が3章程度に集約されているか
- [ ] データシートに眠っていた有用データを使い切ったか
- [ ] ご相談事項（意思決定要請）が明確になっているか
