## 学び1【最重要】：他クライアント情報の混入

### 何が起きたか

私の初稿に「**ファンクル抜きの実売上トレンド**」という分析軸が含まれていた。

しかし「ファンクル」は **エテルナム様（コスメ）**で使われていた楽天モニター施策名であり、
ワイプロジェクトグループ様（牧草）には全く関係ない。

過去にエテルナム様の月次提案を作った際の文脈が、別案件で意図せず再利用された。

### なぜ起きたか

- 同じセッション内で複数クライアントの分析を続けて行ったため、概念が混ざった
- 「ファンクル抜き売上」というフレームを **クライアント固有のフレームと認識せず**、
  汎用的な分析軸として誤用してしまった

### 教訓

**core-rules/data-hygiene.md** に「クライアント情報の絶対分離」を明文化。
作業前・作業中・作業後の3段階チェックを必須化。

## 学び3：データ活用の漏れ

### 私が見逃していたデータ

エクセルファイルの中に以下が入っていたが、私は十分活用しなかった：

1. **アイテムリーチ実績テーブル**（平日／5のつく日／日曜／大型販促別）
   - CPC、CVR、ROAS の傾向が見えるデータ
   - 修正版では専用スライドで「ベースのCPCを抑え、ブーストCPCを上げる」という具体策に繋げている

2. **競合売れ筋データ**（3月、JANコード付き商品のみ）
   - 牧草市場・ネイチャーブリードヤフーショップの推定月間売上情報
   - 修正版では競合比較スライドの根拠データに活用

3. **お試しセット注文者数の推移**（月次）
   - 4月16人、3月15人、2月14人 → 5月目標45人
   - 全体注文者の31%がお試し経由という構造的な発見
   - 修正版では商品別売上スライドに追記

### 教訓

**全シートを一度舐めてから着手**。シート名だけで判断せず、内容を確認。
「これは月次定例で言及しなくていい」と判断したものでも、**他のシートと組み合わせると有用**になる場合あり。

## 学び4：着地推計の精緻化

### Before（私）

- 通常日平均×残日数で機械的に計算 → 197,700円

### After（修正版）

- 残日数の各日に **販促カレンダーに合わせた売上見込み**を置く
  - 4/27 5,000円、4/28 7,500円、4/29 7,500円、4/30 5,000円
- → 着地 200,904円

### 教訓

着地推計は「カレンダー連動の根拠ある数値」で組む。
質問されたら「なぜその金額か」を説明できる状態にする。

## 学び5：トーンの調整

### Before（私）

- 「目標達成率99% → 達成圏」（楽観的）

### After（修正版）

- 「目標達成率100% → ギリギリのライン。残りすべての日程で目標達成する必要あり」（緊張感）

### 教訓

クライアントへの月次報告では、**適度な緊張感**を共有することで残期間の施策が動きやすくなる。
過度に楽観的な表現は施策意欲を削ぐ。

## 学び6：施策の「想定効果」を数値化

### Before（私）

| 施策 | 想定効果 |
|------|---------|
| ボーナスストア5% | 日次平均6,000円の底支え |
| 5のつく日ブースト | 通常日比 約2倍の売上 |
| ウルトラ爆買WEEK | 4月爆買week超えを目指す |

### After（修正版）

| 施策 | 想定効果 |
|------|---------|
| 日曜日・5のつく日クーポン | 売上1.5万円目標 |
| ウルトラ爆買WEEK | 売上20万円、新規獲得注文者数:30 |
| アイテムリーチCPC調整 | ROAS200%以上維持しつつ経由売上15万円 |

### 教訓

**想定効果は具体的な数値で書く**。「底支え」「2倍」のような表現は弱い。

## 学び7：4/18売上ゼロを過剰に深掘りしすぎた

### Before（私）

- 専用スライドを作成、4つの仮説を並列で記載
  1. クーポン設定が4/18のみ対象外
  2. 主力商品の在庫切れ
  3. 楽天ロジ移行で配送日表記が極端
  4. 計測タイミングの遅延

### After（修正版）

- 爆買week効果検証の表内に1行記載のみ
- 表の備考欄を空白で。「在庫切れ影響あり」程度の事実記述

### 教訓

**1日だけの異常値に専用スライドは不要**。
表内コメントで十分。仮説4つ並べるより、確認アクション1つに絞る方が建設的。

## 学び8：曜日の確認漏れ

### Before（私）

- 4/17(木)、4/18(金)、4/19(土) と表記

### After（修正版）

- 4/17(金)、4/18(土)、4/19(日) ← 正しい

### 教訓

曜日は **必ず一次データから**取る。推測で書かない。

```python
import datetime
print(datetime.date(2026, 4, 17).strftime('%A'))  # Friday
```

## 学び9：優良配送スライドの推奨度を消す

### Before（私）

- A/B/C/D の4選択肢に「推奨度」列を追加し、Cを「高」と推奨

### After（修正版）

情報を整えて判断材料を提示するに留める方が良い場合が多い。
